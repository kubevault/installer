## OLM bundle

KubeVault can be installed through [OLM](https://olm.operatorframework.io/) (including OpenShift
OperatorHub). The bundle uses `installer.kubevault.com/v1`, kind `Kubevault`, and a Helm operator
(`quay.io/operator-framework/helm-operator`) that reconciles `charts/kubevault`. The `Kubevault`
spec is the values file of that chart. cert-manager must be installed in the cluster because the
operator issues the webhook serving certificate with it (see `watches.yaml`).

Layout (follows [kubedb/installer](https://github.com/kubedb/installer)):

| Path | Purpose |
|------|---------|
| `olm.mk` | OLM targets, included from `Makefile` |
| `watches.yaml`, `Dockerfile` | helm-operator image that embeds `charts/kubevault` |
| `config/` | kustomize sources for the bundle (CSV base in `config/manifests/bases`) |
| `config/rbac/custom_role.yaml` | generated by `make gen-custom-role` from the rules of the chart |
| `bundle/`, `bundle.Dockerfile` | generated bundle; do not hand-edit except `bundle/metadata/dependencies.yaml` |

With Docker, Helm, kustomize, yq and operator-sdk installed:

```bash
make update-chart-dependencies   # the image embeds charts/kubevault/charts
make docker-build                # operator image: ghcr.io/kubevault/kubevault-installer:$(VERSION)
make bundle                      # regenerate + validate the bundle
make bundle-build                # bundle image
```

Override `VERSION`, `IMG`, `BUNDLE_IMG`, `CHANNELS` and `DEFAULT_CHANNEL` as needed. Before a
release, `make bundle-replace-image-digest PREV_VERSION=<previous tag>` resolves image references
to digests, and sets `relatedImages` and `replaces`. Test on a cluster with `make olm-install`
followed by `make run-bundle`.

`make gen-crds` copies the `Kubevault` CRD into `config/crd/bases` and `bundle/manifests`.
